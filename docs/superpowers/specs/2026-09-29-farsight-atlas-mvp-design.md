# Farsight — Atlas MVP design

Date: 2026-09-29 · Status: draft for review

Farsight is a private companion site for the crew's Valheim servers: a world
atlas rebuilt from every autosave, plus who is online and how to join. The full
product is designed in Claude Design (`design/World Atlas.dc.html`, Organic
design system). This spec covers **sub-project 1, the Atlas MVP**. Later
sub-projects (activity timeline, player profiles, save diffing, time & weather,
admin settings UI) get their own spec → plan → build cycles.

## Goals

1. A zoomable map per Valheim server whose terrain is generated from the world
   seed and whose markers come from the latest autosave, refreshed within a
   minute of each save.
2. A server card: online now, recently online, version, uptime, world
   progression (bosses, day, explored %), world rules, and how to join
   (live crossplay join code or address).
3. All three Valheim instances (`mulevikings`, `mulevikings-old`,
   `muleadventure`) from day one, switchable in the UI.
4. Desktop and mobile layouts from the design, including its states
   (offline, nobody online, first-run charting, stale data).
5. Private: one shared passphrase per server.

## Non-goals (this sub-project)

- Activity timeline, player profiles, "who was on today" strip, deaths list
  over time. Sessions *are* recorded now so those features have history later.
- Diffing saves to derive events (new portals, raids, bosses).
- Time-of-day and weather estimates (needs an EnvMan port).
- An admin Settings UI. Servers are configured through GitOps config.
- Enshrouded servers.
- Player positions. They are never shown (and are not in the save anyway).

## Spike findings this design rests on

A throwaway spike on 2026-09-29 against the live `mulevikings` save proved:

- **Valheim 1.0 chunked saves (world version 41)** are fully decodable from the
  server's own `assembly_valheim.dll`. `<World>/` holds
  `_main.N.chunks` (chunk index: `u16 ver, i32 zdoCount, i32 n, n×{u16 chunk,
  u8 size, u32 version, i32 zdos}`), `XX_YY__size_version.chunk` files
  (`i16 ver, i32 count, ZDO…`), `_main.N.db2` (`i32 ver, f64 netTime`, then a
  gzip ZPackage with generated zones, location version, global keys, locations
  as `{i32 hash, vec3, bool placed}`) and `_main.N.fwl2` (name, seed name,
  seed, world-gen version, modifier presets, platform roster). `_main.N.ok` is
  written last and marks a complete save. Chunk `00_01` holds portals. All
  476,157 ZDOs parsed exactly.
- **ZDO record:** `u16 flags` (bit 0x2000 small int16 position, 0x1000
  rotation, 0xFF extra-data mask), position, `i32 prefab`, optional rotation
  (2 or 4 bytes), then typed key/value lists (floats, vec3, quats, ints, longs,
  strings, byte arrays) keyed by `GetStableHashCode` of the var name.
- **Names:** prefab and location hashes resolve 100% using names from
  `valheim_server_Data/StreamingAssets/SoftRef/manifest{,_extended}`.
- **Terrain from seed:** a port of `WorldGenerator.GetBiome/GetBaseHeight`,
  Unity `Mathf.PerlinNoise` (Perlin 2002 improved noise, `abs()` inputs,
  `(raw + 0.69) / 1.483`) and Unity `Random` (Xorshift128) classifies all
  1,440 location instances into their correct biome (100%) and 97.9% of
  vegetation (misses are player-planted trees and border pixels).
- Two instances still write the **legacy single-file `.db`** (84 MB, 160 MB,
  up to 2.76M ZDOs). Its reader is in the same assembly (`ZDOMan.Load`,
  `ZDO.LoadOldFormat`, `ZoneSystem.LoadOld`).

## Architecture

```
 gameservers namespace (per Valheim pod)            farsight namespace
┌──────────────────────────────────────────┐      ┌──────────────────────────────┐
│ valheim  ──writes──▶ /config/worlds_local │      │ farsight (Go, one binary)     │
│          ──logs────▶ /var/log/supervisor  │      │  ├ ingest API  (agent token)  │
│                                           │      │  ├ tile renderer (worldgen)   │
│ farsight-agent (sidecar, read-only mounts)│─────▶│  ├ web API     (passphrase)   │
│  ├ save watcher → parser → snapshot       │ HTTP │  ├ SvelteKit static UI        │
│  └ log tailer  → live events              │      │  └ SQLite + tile cache on PVC │
└──────────────────────────────────────────┘      └──────────────────────────────┘
```

One Go module, two binaries: `cmd/farsight-agent` and `cmd/farsight`. Shared
packages live in `internal/`.

### Units

| Package | Does | Depends on |
|---|---|---|
| `internal/zpkg` | Little-endian reader for ZPackage primitives (7-bit strings, NumItems, Vector2s, small rotation). | — |
| `internal/save` | Detects save format; streams ZDOs from chunked v41 and legacy `.db`; reads db2/fwl2/fwl metadata. Streaming callback, never holds all ZDOs. | `zpkg` |
| `internal/names` | Stable hash; embedded prefab/location name table generated from the SoftRef manifests (checked in, regenerated by a `go generate` tool). | — |
| `internal/extract` | Callback that keeps only atlas-relevant ZDOs and turns them into a `Snapshot` (see below); clusters building pieces into bases. | `save`, `names` |
| `internal/worldgen` | Unity Random + Perlin ports; `Biome(x,z)`, `Height(x,z)` including `GetBiomeHeight` per biome, lakes, rivers, streams. | — |
| `internal/tiles` | Renders a seed's terrain into a PNG tile pyramid; progress reporting. | `worldgen` |
| `internal/logwatch` | Tails the Valheim stdout log; parses joins, leaves, join codes, version, boot, saves (Steam and crossplay line shapes, per `valheim.mtail`). | — |
| `internal/store` | SQLite: servers, snapshots, sessions, live state. | — |
| `internal/server` | Standard-library `net/http` `ServeMux` (method and path patterns; no chi): ingest endpoints, web JSON API, auth, tiles, static UI. | `store`, `tiles` |
| `web/` | SvelteKit (Svelte 5, static adapter) + Leaflet `CRS.Simple`; Organic `styles.css`. | API |

### farsight-agent (sidecar)

- Added once to `base-valheim/deployment.yaml` in the cloudcluster repo, so all
  three Valheim pods get it (one restart each, done at an idle time).
- Mounts the data PVC `config` subPath **read-only** at `/worlds` and
  `supervisor-logs` read-only. Runs as uid 0 with all capabilities dropped,
  `readOnlyRootFilesystem` and no privilege escalation, like the existing
  mtail sidecar. The supervisor log files are root-owned `0600`. Small
  resources (request 50m/64Mi, limit 1 CPU/768Mi; the file is read into
  memory, up to 160 MB for `muleadventure`, but ZDOs are streamed to the
  extractor and only atlas-relevant ones are kept). A save that changes
  mid-read (old chunk files are deleted once a newer save completes) aborts
  and is retried next poll.
- **Save watcher:** polls every 15 s. Chunked: newest `_main.N.ok` whose N is
  higher than the last processed. Legacy: `<World>.db` mtime changed and stable
  for one more poll (Valheim writes `.db.new` then renames). Parses once,
  builds a `Snapshot`, POSTs it gzip-compressed. If only the POST fails, the
  built snapshot is kept and the POST alone is retried with exponential
  backoff (starts at the poll interval, doubles, capped at 5 minutes; reset on
  success or as soon as a newer save appears) — the save is never re-parsed
  for a POST retry. A save that fails to parse for any reason other than
  changing mid-read or still being written is logged once and skipped until
  the next save id appears; the save files are never touched.
- **Log tailer:** follows both `valheim-server-stdout---supervisor-*.log`
  (newest file, reopens on rotation) and `supervisord.log`. Stop events come
  from supervisord, not the game log, since the game logs nothing on stop:
  its `stopped:`/`exited:` lines become `server_stopped`, its `spawned:`
  lines become `server_starting`. Log timestamps are the game container's
  local wall-clock time with no offset, so `FARSIGHT_LOG_TZ` must equal the
  game container's `TZ` (default `UTC`, which is also what an unset `TZ`
  means): `mulevikings` sets `TZ=Europe/Oslo`, the other instances leave it
  unset and log UTC. On startup the agent warns if the newest server-log
  line is more than 30 minutes from the file's mtime, which means the two
  don't match. Each log stream resolves the repeated hour on the DST
  fall-back day by its own history (the earlier instant, unless that would
  go back in time). Sessions are timed from character spawn. Event types: `server_starting`, `server_boot{version,
  networkVersion}`, `server_ready`, `server_stopped`, `join_code{code}`,
  `players_now{players}`, `player_join{name,platform,platformId}`,
  `player_leave{name,platform,platformId,since,seconds,reason}`,
  `world_saved`, `heartbeat`. Events POST in small batches as
  `{"events":[…]}`; on startup the tailer replays the existing file so a
  restarted sidecar rebuilds today's state; the central side dedupes by
  `id` per server. Heartbeats are not queued behind a backlog: the latest
  one rides at the head of the next POST. A batch rejected with 400, 413 or
  422 is logged and dropped; any other failure is retried with backoff.
- **Event contract rules for the central app:**
  - `supervisor-logs` is an `emptyDir`, so a pod restart loses both logs:
    the agent never emits leaves for players online when the pod died, and
    usually no `server_stopped` either.
  - So central closes every open session for a server on `server_starting`,
    `server_boot` or `server_stopped`, or after 3 minutes without a
    heartbeat, with end = that server's last heartbeat or event time. This
    applies even when the pod comes back within 3 minutes.
  - A `player_leave` pairs with its `player_join` on
    `(serverId, platformId, name, since == join.at)`.
  - A leave may arrive without its join, and a join without its leave
    (queue drop-oldest, or a replay starting mid-session after rotation);
    both are tolerated.
  - `seconds` is omitted when 0; `players` is present even when 0.
  - Event ids are unique per server only: dedupe on `(serverId, id)`.
  - The endpoint answers 2xx for a batch and skips invalid events one by
    one rather than rejecting the batch.
  - Every agent restart replays, and so re-sends, all events since the pod
    started, so dedupe must be cheap.
- Config via env: `FARSIGHT_URL`, `FARSIGHT_SERVER_ID`, `FARSIGHT_TOKEN`
  (sops secret per instance), `WORLD_NAME`.
- The instance's `CiliumNetworkPolicy` gets an egress rule to the farsight
  service on its port.

### Snapshot (agent → farsight)

JSON, one per save (field names and types match `internal/extract/snapshot.go`
exactly — this section is kept in sync with that file):

```
{ serverId, saveId,                                 // saveId e.g. "chunked:123" or "legacy:<mtimeNs>:<size>"
  savedAt,                                          // the game's own save time (chunked: _main.N.ok mtime; legacy: .db mtime)
  readAt,                                           // when this agent extracted the snapshot from that save
  format: "chunked"|"legacy",
  worldVersion,                                     // save.World.Version, e.g. 41
  world: { name, seedName, seed, genVersion, netTime, day, modifiers{}, flags[] },
  globalKeys[],
  bosses: [{ key, name, defeated }],                // in game progression order
  exploredZones: [[x,z]…],                          // 64 m zones
  explored?: { source, cell, size, bits },          // 12 m mask: "tables"|"zones", 12, 2048, base64(gzip(bitset)) (fog spec)
  locations: [{ id, kind, type, label, x, y, z }],  // only types we mark; same shape as markers
  markers: [{ id, kind, x, y, z, label?, owner?, species?, type?, pair? }],
  bases: [{ id, name, x, z, radius, pieces, builders[{id,name?,pieces}] }],
  players: [{ id, name }],                          // from beds/tombstones
  stats: { zdos, pieces, unknownPrefabs } }
```

All array fields are always present as `[]`, never `null`, even for an empty
world. Marker and location `id`s (`kind-N`, e.g. `portal-3`, `loc-12`) are
positional within one snapshot, not stable across snapshots or saves; stable
IDs (for UI deep links and diffing) are a later sub-project's decision, not
part of this contract yet.

Marker kinds in the MVP: `portal` (tag; paired by equal tag, matching the
game's own pairing), `bed` (ownerName), `tame` (species, TamedName;
temporary summons such as `Skeleton_Friendly` are excluded), `tombstone`
(ownerName), `sign` (text), `boss_altar`, `trader`
(Haldor, Hildir, Bog Witch), `dungeon` (crypts, caves, camps; zoom-gated).
**Bases** come from clustering building pieces (ZDOs with a `creator`) on a
16 m grid: occupied cells within two cells of each other (≤ 32 m gap) join the
same base, keeping clusters of ≥ 40 pieces (linear time even for very large
worlds); the name defaults to
"<top builder>'s base". Player IDs map to names through beds' and tombstones'
`owner`/`ownerName`; unknown IDs show as "Unknown builder".

### farsight (central)

- **Ingest:** `POST /ingest/{server}/snapshot`, `POST /ingest/{server}/events`,
  bearer token per server (bcrypt-compared; unknown server and bad token
  both get the same 401, and token checks that need a bcrypt compare are
  rate-limited per IP). Snapshot stored as the server's
  current snapshot plus a row in `snapshots` (kept 14 days for the future diff
  sub-project). Events update `live_state` and open/close `sessions`.
- **Tiles:** when a server's `(seed, genVersion)` has no complete tile set,
  render it in the background: 256 px tiles, zoom 0–5 (32×32 tiles at z5,
  about 2.6 m/px over the 21 km world), biome colours plus hillshade from
  `Height`, oceans by depth. Files cached on the PVC under
  `tiles/{seed}-{genVersion}-r{renderVersion}/{z}/{x}/{y}.png`, rendered in
  parallel. `renderVersion` identifies the tile-drawing logic itself
  (colours, hillshade, downsampling); bumping it re-renders every world from
  scratch into a fresh directory, and old tile sets are garbage-collected
  once their replacement is complete. An unknown `genVersion` (greater than
  `worldgen.MaxGenVersion`) is refused rather than rendered. Progress counts
  all 1,365 tiles of the z0–z5 pyramid (downsampled levels included; `done`
  reaches `total` only once the completion marker is written) and feeds the
  design's "Charting the world for the first time · 28 % · 389 of 1,365
  tiles" state. The rendered terrain tiles on disk are never fogged. Since
  `2026-10-01-fog-tiles-design.md` the **fog is drawn into the served
  tiles** from the 12 m explored mask (it was a client-side canvas before).
  Tiles are served per server, key and fog key at
  `/tiles/{id}/{key}/{fog}/{z}/{x}/{y}.png` (z0–z6), where `key` is the tile
  set's directory name (`{seed}-{genVersion}-r{renderVersion}`), only while
  it is that server's current complete set and `fog` its current fog key,
  with immutable caching.
- **Web API (JSON):** see the API contract below.
- **Auth:** each server has a shared passphrase (bcrypt hash in config).
  `POST /api/unlock {server, passphrase}` sets an HMAC-signed, HttpOnly cookie
  listing unlocked servers (1 year). Share links carry the passphrase in the
  URL fragment (`/#s=mulevikings&k=…`) so it never hits logs; the UI unlocks
  and strips it. Failed unlocks are rate-limited per IP. The server switcher
  lists only unlocked servers. Every `/api/servers…` and `/tiles/…` request
  for a server that isn't unlocked returns 404, not 403, so server ids don't
  leak.
- **Config:** a JSON file, `farsight.json` (`farsight serve -config PATH`,
  default `/etc/farsight/farsight.json`), from a ConfigMap, plus the cookie
  key from sops as the env var `FARSIGHT_COOKIE_KEY` (at least 32 bytes). Per
  server `id, name, address?, crossplay, discordHint?, maxPlayers?,
  passphraseHash, agentTokenHash`; global `listen?, dataDir?, cookieSecure?,
  trustProxy?`. (Amended from the original `farsight.yaml`.)

#### API contract

All times are RFC 3339 UTC strings. Absent optional fields are omitted.

```
GET  /api/servers                         -> {"servers":[ServerSummary]}         (unlocked only, config order)
     ServerSummary = {id, name, status, players, maxPlayers}
GET  /api/servers/{id}                    -> Card
     Card = {
       id, name, crossplay, address?, discordHint?, maxPlayers,
       status: "online"|"starting"|"restarting"|"offline"|"unknown",
       version?, networkVersion?, upSince?, lastHeartbeat?,
       players, joinCode?, joinCodeAt?,
       online:   [{name, platform, platformId, since}],                    (since asc)
       recent:   [{name, platform, platformId, since, until, seconds}],    (ended in last 72 h, until desc, max 50)
       activity: [{type, at, name?, platform?, code?, players?, seconds?, version?}], (last 50 non-heartbeat/players_now events, at desc)
       world?: {name, seedName, day, bosses:[{key,name,defeated}], modifiers:{}, flags:[],
                exploredPct, savedAt, readAt, saveIntervalSec?},
       tiles:  {state:"none"|"queued"|"rendering"|"complete"|"refused", done, total, key?}
     }
GET  /api/servers/{id}/snapshot           -> {savedAt, fogKey, explored, exploredZones, markers, locations, bases, players}
                                             (markers, locations and bases filtered to the explored mask, which also
                                             blanks a kept portal's `pair` when its partner was filtered out, so it
                                             shows as unpaired rather than revealing a hidden partner; 404 if no
                                             snapshot)
GET  /tiles/{id}/{key}/{fog}/{z}/{x}/{y}.png -> PNG, z0–z6 (served when key is the server's current complete set
                                             and fog its current fog key; a stale but well-formed fog key 302s,
                                             Cache-Control: no-store, to the same URL under the current fog key; a
                                             malformed key or a locked server 404s; a served tile's Cache-Control is
                                             public, max-age=31536000, immutable)
POST /api/unlock {server, passphrase}     -> 204 + Set-Cookie | 401 {"error":"wrong passphrase"} | 429 {"error":"too many attempts"}
GET  /healthz                             -> 200 "ok"
```

Status rules, applied at read time:
- `offline` if there has been no heartbeat for 3 min.
- Otherwise `restarting` after `server_stopped`, `starting` after `server_starting` or `server_boot`, and `online` after `server_ready`.
- `unknown` before any event has been seen.

`exploredPct` = explored 12 m cells ÷ cells whose centre lies within 10 500 m (a constant computed once), × 100, rounded to 1 decimal place.

`saveIntervalSec` = the median gap between the last up to 10 `world_saved` events. It's omitted when there are fewer than 3.

### Web UI

SvelteKit static build (adapter-static, SPA fallback) embedded in the Go
binary behind the `webui` build tag: `make web farsight-ui`
builds it. Without the tag the binary serves a placeholder page, so Go builds
and `go test ./...` never need Node. Organic `styles.css` and Lucide icons at
stroke-width 2.75, light/dark as in the design (dark by default, persisted in
`localStorage`). Fonts (Caprasimo, Figtree) are self-hosted via @fontsource,
and the page makes no third-party request: no CDN, no analytics, a
`'self'`-only CSP.

Servers are unlocked in an Organic unlock dialog (server id and passphrase).
It is full screen while nothing is unlocked, and it opens from the switcher's
"Add a server…". A share link `/#s=<id>&k=<passphrase>` unlocks and at once
becomes `/#s=<id>`; the passphrase is never stored.

Where the design leaves gaps or is ambiguous, the MVP adaptations are listed
in [`design/DESIGN-NOTES.md`](../../../design/DESIGN-NOTES.md) and decided in
the "Rulings on design ambiguities" table of
[plan 4b](../plans/2026-09-30-plan4b-web-ui.md). Built to the design file's
sections:

- **01 Desktop main view:** full-bleed Leaflet map (`CRS.Simple`, world
  metres → tile pixels, north up), a custom greedy clusterer (26 px radius,
  the selected pin never clustered, off at max zoom) instead of a marker
  clustering plugin, layer toggles with
  counts, portal connection lines, search over labels (portal tags, tame
  names, base names and builders, sign text, boss names), "Map updated N min
  ago · next save in ~M min" pill (save interval learnt from recent saves),
  server card side panel.
- **02 Mobile:** map fills the screen, players in a bottom sheet, search and
  layers from the top-bar menu.
- **03 Marker details** use the design's `MarkerCard` (popover on desktop,
  floating card on mobile) and the world progression panel (bosses from
  `defeated_*` global keys, in-game day, explored % of land zones).
- **04 States:** server offline (log shows shutdown, or no agent heartbeat
  for 3 min),
  nobody online, first-run charting, stale snapshot (> 2 save intervals old).
- **06 How to join:** crossplay join code (from the log, updates by itself),
  or address for Steam servers, version, password hint (never the password),
  world rules card.
- **07 Multiple servers:** switcher over unlocked servers.

Sections 05 (timeline) and 08 (profiles, time & weather) are later
sub-projects. The card's "Recent activity" list shows only log events in the
MVP.

## Error handling

- Agent: a parse error on one save (other than the save changing mid-read or
  still being written, which are retried on the next poll without an error
  log) is logged once at error level with the save id and skipped, until
  `LatestSave` reports a different save id; the previous snapshot stays
  current and the UI shows "stale" once it ages out. If only the POST to
  farsight fails, the already-built snapshot is retried with backoff, not
  re-parsed. An unknown world version fails loudly (logged) rather than
  guessing.
- Unknown prefab hashes are counted and reported in the snapshot's
  `stats.unknownPrefabs`, so a game update that adds content is visible.
- Central: invalid snapshots are rejected with 400 and not stored. Tile
  rendering is resumable (skips existing tiles) and restarts after a crash.
- Log tailer tolerates truncation and rotation. Replayed events carry the
  same deterministic ids as the first time, and central dedupes them by `id`
  per server. Events are pruned after 14 days, so central refuses events
  older than 13 days rather than re-applying a replay of pruned ones.

## Testing

- `zpkg`, `save`: unit tests on small real fixtures (a portal chunk, a 46-byte
  chunk, the `.chunks` index, db2, fwl2) plus a trimmed legacy `.db`. A golden
  test on a full `mulevikings` save (kept out of git, pulled by a make target)
  asserts 476,157 ZDOs, 16 portals / 8 pairs, 14 beds, 12 tames.
- `worldgen`: `FjordSeed` offsets are `(3119, 4451, 2181, -5622, -5640)`;
  biome oracle test ≥ 99.9 % on the golden save's location instances; height
  oracle compares `Height(x,z)` with the `y` of naturally placed vegetation
  ZDOs (median error target < 1 m; this is how rivers and lakes are verified).
- `logwatch`: tests against `hack/fixtures/valheim-crossplay.log` from the
  cloudcluster repo plus a Steam fixture.
- `api`: httptest for auth (unlock, cookie, rate limit), ingest token checks,
  explored-zone filtering.
- Web: Vitest unit tests for the logic outside components (API client, app
  state, formatters, derived state, markers, clustering, search, geometry,
  fog masks, share links, clipboard), and Playwright e2e in
  a `desktop` (1440×900) and a `mobile` (390×844, touch) project against a
  real `farsight serve` seeded by `cmd/farsight-seed` (fixture snapshot and
  events with invented names, times shifted to now, a fake complete tile set
  written before serve starts, and a heartbeat keep-alive). Card states
  (offline, empty, charting, stale, refused) are covered by route overrides
  of the real card. `hack/playwright-libs.sh` supplies Chromium's system
  libraries and a fontconfig file without root; CI uses
  `playwright install --with-deps`. `make e2e` runs it.

## Risks

- **River/lake port** is the least verified part. Fallback: ship with biomes
  and base heights (already correct) and add rivers once the height oracle
  passes.
- **Game updates** can change the save format or world generation. Mitigated
  by version checks, the unknown-prefab counter, and regenerating the name
  table from the new SoftRef manifest.
- **Iron Gate code ports** (world generation, save format). The repo became
  public on 2026-09-30 at the owner's request, so these ports would be published.
  That is a licensing risk the owner must confirm before the first push. Never commit decompiled
  source (`reference/`) or real save or log data.
